## Information Path

Training has two separate style-related paths:

1. Target-construction path:
   `content, target_style -> SAT/DWT target -> target_delta -> FM loss`.
   This path defines what the velocity should be, but it is not a model condition path.

2. Model-condition path:
   `target_style_id -> style_memory -> patch_proj -> block cross-attention -> shared backbone -> velocity heads`.
   In the delivered baseline, this is the only active style condition path.

The missing path is:

`target_style latent -> style tokens / velocity head`.

The baseline receives gradients through `target_style` because it is used to build the supervised target, but changing `target_style` while holding `style_id` fixed does not change model velocity at all.

## Theory

The current architecture can learn a per-style average style direction, not an instance-specific reference style. That follows directly from the active condition graph: the model reads `style_id`, not `target_style`. The target image affects the supervised velocity target, but the model cannot condition its prediction on the particular target latent except through the coarse discrete style id.

This explains why endpoint AdaIN is such a strong lever: it is outside the learned velocity field and directly reads the reference latent statistics at inference. It supplies an instance-specific style path that the network itself lacks.

So the right place to improve style learning is upstream of cross-attention or in the velocity heads, where the FM loss can train the style path. Output AdaIN remains useful, but it is a post-hoc statistic operation; it cannot teach the velocity field to use reference style information.
