# Destructive Ablation Plan

## Goal
逐个**去掉**T5中的组件，证明哪些掉性能（=有效必须保留），哪些不掉（=冗余可删）。

## Scope
- 训练侧：从T5 ep7 resume，训练3ep（ep8-10），比较ep10性能
- 推理侧：直接在T5 ep7 checkpoint上改推理参数
- 参数消融：关键超参数的连续值扫描
- 非目标：不做性能提升实验，不做正向添加实验

## Current State & Constraints
- T5 ep7 baseline: all_clip=0.7307, all_lpips=0.3403
- T5原版ep10: all_clip=0.7299, all_lpips=0.3419
- 训练方法：resume from T5 ep7, resume_training_state=True, resume_optimizer=True, num_epochs=10
- 每组3ep≈7.5min，20h≈160组容量
- 远程：Windows Python, schtasks后台, I盘

## Code Compatibility Risks (已验证)

### 不能用的改动（会crash或无效果）
| 改动 | 原因 |
|------|------|
| spectral_ode_enabled=False | **Dead code** — 字段存在但从未读取。spectral_ode由contract_family控制 |
| style_gate_mode="none" | **无效** — 不在枚举中，静默回退到tanh_gate。正确方式：用"film_only"（gate=0） |
| lowpass_mode="none" | **无效** — 不在枚举中，回退到avg_pool。无法禁用低通滤波 |
| endpoint_head_mode="direct" | **无效** — 不在枚举中，回退到"velocity" |
| skip_fusion_mode="none" | **无效+危险** — 回退到concat_conv，改变参数数量，破坏resume |
| body_block_type="conv" | **危险** — 改变参数数量，破坏resume |
| color_highway_gain=0 | **Dead code** — 字段存储但从未在forward中使用 |

### 正确可用的替代方案
| 原始意图 | 正确做法 |
|----------|----------|
| 去spectral_ode | 设spectral_ode_levels=0（但需验证代码是否支持0）或改contract_family |
| 去style gate | style_gate_mode="film_only"（gate=0，零化cross-attn输出） |
| 去低通滤波 | lowpass_mode="avg_pool"（已有I10数据：lpips+0.047） |
| 去body attention | 无法安全做（改参数数量）。可做推理侧替代：设semantic_attn_temperature→极大值 |
| 去color highway | 无法通过gain=0做（dead code）。需看代码中highway_proj如何使用 |

### 优化：合并D2+P1, D3+P2
- D2(adain=0) 已包含在P1(0,0.25,0.5,1.0)中
- D3(alpha=0) 已包含在P2(0,0.05,0.1,0.2)中
- L2(w_endpoint_style=0) 已包含在P4(0,2,4,8,16)中
- L4(single_step_swd=0) 已包含在P5(0,2,4,8)中

因此实际独立实验数 = 18-4(架构去重) + 12-2(loss去重) + 24(参数) + 8(推理) = **56组**

但P1/P2/P4/P5的0值点已含在参数扫描中，实际去重后约50组。
