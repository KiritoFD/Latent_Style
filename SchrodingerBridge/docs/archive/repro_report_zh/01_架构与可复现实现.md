## 3. 理论基础：latent-space Schrodinger Bridge 与风格迁移

本节给出当前方法的理论解释，目标是让代码里的每个模块都能对应到清晰的数学角色。需要强调的是：当前实现不是完整求解连续时间 Schrodinger Bridge 的严格数值算法，而是在工程上可训练、可扩展的 latent-space 近似。论文里建议使用 “bridge-inspired probability flow” 或 “Schrodinger-Bridge-inspired latent transport” 这类严谨表述。

### 3.1 为什么放在 latent 空间

像素空间风格迁移同时面对两个困难：

```text
1. 图像维度高，直接学习 transport path 成本大；
2. 艺术风格大量表现为颜色、纹理、局部统计，而内容结构又需要保持。
```

当前方法先把图像压到 VAE latent：

```text
x image -> z latent,  z in R^{4 x 32 x 32}
```

这样做有三层意义：

| 角度 | 作用 |
|---|---|
| 计算效率 | 256 图像对应 4x32x32 latent，训练和推理远低于像素空间 |
| 结构抽象 | VAE latent 已经编码了低频结构和语义布局，速度场更容易学到“改风格但不毁内容” |
| 分布匹配 | SWD / patch distribution matching 在 latent/feature 上更稳定，不需要直接对 RGB 像素做刚性约束 |

因此论文主线应强调：

```text
We learn the artistic transfer path in a compact latent space rather than in RGB space.
```

这也是方法能够低显存、快速训练和快速推理的基础。

### 3.2 从图像风格迁移到条件概率流

给定内容 latent `z_0` 和目标风格 `s`，模型学习一个风格条件速度场：

```text
v_theta(z_t, t, s)
```

推理时用显式 Euler 积分：

```text
z_{t+dt} = z_t + v_theta(z_t, t, s) * dt
```

积分终点 `z_1` 解码后得到风格化图像。这个形式把风格迁移从“一步图像变换”改写成“沿条件速度场移动”的问题。

理论直觉是：

```text
content image distribution  ---- style-conditioned flow ----> target artistic domain
```

这与 Optimal Transport / Schrodinger Bridge 的联系在于：我们希望找到一条从内容样本到目标风格域的低代价路径。路径既要到达目标风格分布，又不能以破坏内容为代价走得过远。

### 3.3 Schrodinger Bridge 视角

经典 Schrodinger Bridge 问题可以理解为：在给定起点分布和终点分布的条件下，寻找一条最接近参考随机过程、总代价最小的概率路径。对本任务而言，可以类比为：

| SB 概念 | 当前实现中的对应 |
|---|---|
| 起点分布 | content latent / source domain latent |
| 终点分布 | target artistic style domain |
| 路径 | latent ODE integration trajectory |
| 控制/漂移 | neural velocity field `v_theta` |
| 路径代价 | kinetic regularization |
| 终点约束 | terminal SWD / style distribution matching |
| 条件变量 | target style id / style spatial prior |

当前实现没有显式训练 forward/backward score，也没有求解严格的 entropic SB dual objective；它采用的是更轻量的 OMF-style endpoint training：

```python
pred_velocity = model(content, t=1, style_id=target_style_id)
pred_endpoint = content + pred_velocity
```

这可以看成把连续路径训练压缩为“一步终点近似 + 推理时多步积分”。优点是训练稳定、工程成本低；缺点是理论上不是严格 SB 求解器，因此论文中应称为：

```text
latent bridge-inspired probability flow
```

而不是宣称完整求解 Schrodinger Bridge。

### 3.4 Optimal Transport 视角：为什么是 SWD

风格迁移没有逐像素 ground truth。目标不是让输出和某一张 style 图像像素对齐，而是让输出落在目标艺术风格分布中。因此终点约束应是分布级别的：

```text
P(output patches | target style) ≈ P(real style patches | target style)
```

当前使用 Sliced Wasserstein Distance。它的直觉是：高维分布很难直接比较，但可以投影到许多一维方向，在一维上排序后计算 Wasserstein 距离，再对多个投影平均。

简化写法：

```text
SWD(P, Q) = E_theta W_2( <theta, P>, <theta, Q> )
```

使用 SWD 的原因：

| 原因 | 说明 |
|---|---|
| 不需要配对监督 | 只需要 output patch set 和 target style patch set |
| 比 Gram 更分布化 | Gram 匹配二阶统计，SWD 能比较投影分布形状 |
| 比全局 FID 更局部 | patch-level SWD 更接近风格纹理和笔触统计 |
| 计算可控 | 多投影一维排序比完整 OT 便宜 |

当前实现还加入 semantic-guided SWD：投影方向不是完全随机，而是从 semantic key / style-relevant feature 中选择响应强的方向。这使得 SWD 更偏向比较与风格有关的 latent/feature 维度，而不是平均地惩罚所有维度。

### 3.5 Kinetic regularization：最小形变原则

如果只有 terminal SWD，模型可以通过大幅改变 latent 来追求风格，导致内容崩坏。因此加入：

```text
L_kinetic = E ||v_theta(z_t, t, s)||^2
```

它对应 OT/SB 里的路径能量或控制代价。直觉是：

```text
在满足风格终点约束的同时，让 latent 移动距离尽量小。
```

这就是内容保持的理论来源。破坏性消融正好验证了这一点：

```text
w/o kinetic:
CLIP-S 0.7159, 但 CLIP-C 0.6624, LPIPS 0.6375
```

也就是说，没有动能约束时，模型仍能学到风格信号，但不再尊重内容拓扑。

### 3.6 Terminal SWD 与 kinetic 的 Pareto 张力

当前方法最重要的科学现象是 style-content Pareto trade-off：

```text
terminal SWD 越强，越靠近目标风格分布；
kinetic / skip / content-preserving constraint 越强，越靠近原内容。
```

两者不是简单可以同时无限增强的目标。实验中：

```text
w/o terminal SWD:
CLIP-S 0.6708, CLIP-C 0.8989, LPIPS 0.3490

w/o kinetic:
CLIP-S 0.7159, CLIP-C 0.6624, LPIPS 0.6375
```

这说明 terminal SWD 和 kinetic 分别控制 Pareto 曲线的两端。论文里应把这点作为方法解释和消融分析的核心，而不是只说“某个 loss 有用”。

### 3.7 Style-id spatial prior：多风格能力的来源

当前方法不是 arbitrary reference-image style transfer。它的条件输入是 style id，对应一个 learnable domain-level style prior：

```python
style_spatial_id_16[num_styles, channels, 16, 16]
```

理论上它是每个艺术域的可学习原型测度。它不描述单张参考图的细节，而描述一个 domain 的平均风格偏置：

```text
Monet domain prior
Van Gogh domain prior
Cezanne domain prior
Hayao domain prior
```

优点是推理不需要 reference image encoder、速度快、参数少、多风格扩展清楚；限制是 raw style 上限受 domain prior 容量限制，无法复现单张 style reference 的独特笔触，也容易学习到 domain 平均色调而不是复杂局部纹理。

这解释了为什么 Ours 在内容和干净度上强，但 raw CLIP-style 与 SaMST 仍然接近而非碾压。

### 3.8 Semantic cross-attention：从风格原型到局部 transport

`SemanticCrossAttn` 的作用是把内容 feature 与 style spatial prior 对齐。形式上：

```text
Q = f_content(x)
K,V = f_style(style_prior)
A = softmax(QK^T / tau)
painted = A V
```

它不是普通“加一个风格向量”，而是局部位置到风格原型 token 的软匹配。可以把它解释为一个低成本的 relaxed transport plan：

```text
每个内容位置从 style prior 的若干位置/通道中取风格信息。
```

默认 softmax 是 row-normalized：每个内容位置会分配一份风格信息，但不保证每个风格位置被均匀使用。这就是后来测试 Sinkhorn routing 的理论动机。

### 3.9 Sinkhorn routing 的严谨解释

新增的 `semantic_attn_routing_mode="sinkhorn"` 试图把 attention 矩阵变成近似双随机矩阵：

```text
row sum ≈ 1, column sum ≈ 1
```

理论动机是避免少数 style token 被过度使用，同时避免大量 style token 被忽略。它更接近 OT coupling 的“质量守恒”直觉。

但这里必须严谨：当前 Sinkhorn routing 不是严格 OT 求解。原因是 logits 来自 learned attention，不是显式 cost matrix；style prior 是 learnable prototype，不是真实 style empirical samples；训练目标也没有完整 entropic OT dual objective。

因此论文里建议表述为：

```text
We optionally use a Sinkhorn-normalized semantic routing to encourage
approximately balanced use of style tokens.
```

而不是：

```text
We solve exact OT inside attention.
```

实验结果也支持“它是稳定性正则而不是 style 增强器”：Sinkhorn 改善 LPIPS/EC，但 raw CLIP-style 稍降。

### 3.10 Entropy-gated kinetic：不确定区域更强刹车

普通 kinetic 对所有位置施加相同约束：

```text
mean(||v||^2)
```

但不同区域的可迁移性不同。天空、墙面等低结构区域可以更自由地改变；树枝、轮廓、建筑边缘等复杂区域需要更强保护。Semantic attention 的 entropy 可以作为局部不确定性的代理：

```text
entropy(A_i) 高：该内容位置找不到确定风格匹配
entropy(A_i) 低：该内容位置匹配明确
```

于是新增：

```text
L_kinetic = mean(||v||^2 * (1 + lambda * entropy))
```

理论解释是：在 transport 不确定的位置提高路径代价，降低结构破坏风险。实验上它提升 EC/content/LPIPS，但 raw style 降低。这符合理论预期：它更像 adaptive content-preserving regularizer，而不是风格增强器。

### 3.11 Gumbel / hard color transport：为什么不作为主线

局部 contextual color loss 可以看成把输出局部颜色分布向目标风格颜色分布拉近。softmax transport 是 barycentric projection：

```text
warped = A V
```

这会平均多个候选颜色，可能导致颜色发灰；Gumbel hard transport 则近似 Monge map：每个位置选择一个更硬的颜色匹配。

理论上它可能提升表面色彩和局部纹理锐度。但当前实验显示 raw style 略升，content / LPIPS 明显变差。原因是颜色硬匹配只解决局部表面统计，不能保证全局内容拓扑和风格结构一致。对本方法主线而言，它属于高风险 style booster，不应作为默认设置。

### 3.12 与 SaMST 的理论差异

SaMST 更像高效的 multi-style representation / feed-forward transfer 方法，优势是 raw style 和结构指标强。但当前观察到的问题是 grain/muddy artifact：它可能保留了低频结构，并生成了能被 CLIP-style 捕捉的风格纹理，却在局部笔触真实性上不足。

Ours 的理论优势不在于所有 raw style 指标都压过 SaMST，而在于：

```text
1. kinetic 约束带来更可控的最小形变；
2. SWD 带来分布级风格约束；
3. latent bridge 使输出更平滑干净；
4. artifact-sensitive 指标上更接近真实绘画纹理。
```

因此论文比较时要避免用 SSIM/Edge-F1 这种会奖励 SaMST 低频结构的指标作为唯一证据，而要联合 LPIPS、CLIP-style/content、Gram、FID/KID/CLIP-FID、ArtFID、HF-Patch-KID、MUSIQ/MANIQA 和 user study。

### 3.13 可以放进论文 Method 的一句话版本

推荐方法章节核心描述：

```text
We formulate multi-style artistic transfer as a style-conditioned latent
probability flow. A neural velocity field transports content latents toward
target artistic domains, where terminal sliced-Wasserstein matching enforces
style distribution alignment and kinetic regularization preserves content by
penalizing excessive latent displacement. A learnable style spatial prior and
semantic cross-attention provide an efficient domain-level approximation to
local style transport, enabling fast multi-style inference without per-image
optimization or diffusion sampling.
```

中文对应：

```text
我们把多风格艺术迁移建模为风格条件 latent 概率流。神经速度场将内容 latent
传输到目标艺术域；终端 SWD 负责风格分布对齐，动能正则限制过度位移以保持内容。
可学习 style spatial prior 与 semantic cross-attention 提供了高效的 domain-level
局部风格 transport 近似，从而避免逐图优化和扩散采样。
```

## 4. 模型结构

当前主模型是：

```python
TimeConditionedLANCETBridge(LatentAdaCUT)
```

核心解释：

```text
v_theta(z_t, t, style_id)
```

模型输出不是最终图像，而是 latent 空间中的 velocity / delta。推理时通过 ODE integration 从 content latent 出发积分到目标风格域。

### 4.1 Time-conditioned style code

`src/model.py` 中：

```python
style_code = encode_style_id(style_id)
time_code = time_mlp(sinusoidal_time_embedding(t))
style_code_t = style_code + time_code
```

这表示不同时间步下的同一 style id 有不同的 vector-field 条件。

### 4.2 Backbone encoder

`LatentAdaCUT` 输入为 `[B, 4, 32, 32]` latent：

1. `enc_in`: 4 channel latent 提升到 `lift_channels=128`
2. `hires_body`: 32x32 高分辨率 blocks
3. `down`: 32x32 -> 16x16，channel 提升到 `body_channels=base_dim*2=128`
4. `body_blocks`: 多个 `SemanticCrossAttn`
5. `dec_up`: 16x16 -> 32x32
6. skip fusion
7. decoder blocks
8. `dec_out`: 输出 velocity latent

当前主配置：

```json
"base_dim": 64,
"lift_channels": 128,
"num_hires_blocks": 2,
"num_res_blocks": 4,
"num_decoder_blocks": 2,
"body_block_type": "global_attn",
"decoder_block_type": "conv"
```

### 4.3 Style spatial prior

模型保存一个 learnable style spatial prior：

```python
self.style_spatial_id_16 = nn.Parameter(
    torch.zeros(num_styles, body_channels, 16, 16)
)
```

配置控制预增益：

```json
"style_spatial_pre_gain_16": 0.35
```

该 prior 是当前多风格/domain-level 风格表达的核心。它不依赖 reference image，因此速度快，但也解释了 raw style 天花板：它学习的是 style/domain prior，而不是每张 reference 的具体纹理。

### 4.4 SemanticCrossAttn

`SemanticCrossAttn` 在 16x16 特征上执行 content feature 到 style spatial prior 的 cross attention：

```python
q = to_q(instance_norm(norm_x(x)))
k = to_k(instance_norm(norm_s(style_map)))
v = to_v(norm_s(style_map))
attn = softmax(q @ k / temperature)
painted = attn @ v
delta = painted * (1 + gamma) * learned_gate
```

默认 routing：

```json
"semantic_attn_routing_mode": "softmax"
```

新增可选 routing：

```json
"semantic_attn_routing_mode": "sinkhorn",
"semantic_sinkhorn_iters": 3
```

注意：Sinkhorn routing 是实验性开关。它更像 doubly-normalized semantic routing regularizer，不应在论文中过度宣称为严格 OT plan，因为这里的 style map 是 learnable domain prior，不是完整 empirical style measure。

### 4.5 Skip fusion

当前主配置：

```json
"skip_fusion_mode": "add_proj",
"skip_routing_mode": "add_proj"
```

skip 路径连接 encoder 的 32x32 clean structure 到 decoder。它是内容结构保持的重要机制。破坏性消融显示禁用 skip routing 会伤害结果，但不是最主要风格瓶颈。

### 4.6 Velocity head

`src/model.py` 覆盖 `_compute_delta()`：

```python
raw_delta = self.dec_out(h)
if velocity_head_mode == "tanh":
    raw_delta = tanh(raw_delta) * velocity_tanh_limit
return raw_delta * latent_scale_factor * residual_gain
```

当前默认：

```json
"velocity_head_mode": "identity",
"residual_gain": 1.0,
"latent_scale_factor": 0.18215
```

### 4.7 推理积分

推理入口：

```python
model.integrate(x, style_id, num_steps=12, step_size=1.0)
```

当前逻辑：

```python
horizon = clamp(step_size * style_strength, 0, 1)
dt = horizon / num_steps
for step:
    velocity = model(h, t)
    h = h + velocity * dt
```

重要发现：当前 `horizon` 被 clamp 到 `1.0`。因此只提高 `step_size>1` 不会真的增强风格。这是下一步最值得改的 style-release 方向。

推荐新增开关：

```json
"max_integration_horizon": 1.25 或 1.5
```

## 5. 训练目标

当前主训练目标为：

```json
"objective_mode": "omf",
"loss_type": "omf"
```

训练时固定：

```python
t_fixed = 1
pred_velocity = model(content, t=1, style_id=target_style_id)
pred_endpoint = content + pred_velocity
```

主损失由以下部分构成。

### 5.1 Kinetic regularization

默认：

```python
kinetic_loss = mean(pred_velocity^2)
loss += w_kinetic * kinetic_loss
```

当前主配置：

```json
"w_kinetic": 1.0
```

Kinetic 是内容保持核心。消融 `w/o kinetic` 显示：

```text
CLIP-S 0.7159 但 CLIP-C 0.6624, LPIPS 0.6375
```

解释：没有 kinetic 时，style 可能更强，但内容结构崩坏。

### 5.2 Terminal SWD

Terminal SWD 是风格分布匹配核心。

当前主配置：

```json
"terminal_swd_weight": 20.0,
"swd_use_high_freq": false,
"swd_num_projections": 64,
"swd_patch_sizes": [3, 5, 7, 15]
```

默认路径：

```python
swd_loss = semantic_guided_swd(pred_endpoint, target_style, semantic_k)
loss += terminal_swd_weight * swd_loss
```

消融 `w/o terminal SWD`：

```text
CLIP-S 0.6708, CLIP-C 0.8989, LPIPS 0.3490
```

解释：没有 terminal SWD，模型退化为强内容保持/弱风格化。

### 5.3 Semantic-guided SWD

如果有 `semantic_k`，SWD 投影轴不随机，而从 semantic key 中选择强响应方向：

```python
semantic_scores = abs(k_matrix).mean(dim=1)
idx = topk(semantic_scores)
semantic_axes = gather(target_flat, idx)
theta = normalize(semantic_axes)
```

这是当前方法比简单 SWD 更贴近风格语义的关键之一。

### 6.2 Entropy-gated kinetic

配置：

```json
"bridge": {
  "kinetic_entropy_gate_weight": 2.5 或 5.0
}
```

实现位置：

```text
src/losses.py
```

核心计算：

```python
entropy = -sum(attn * log(attn), dim=-1) / log(num_keys)
kinetic_loss = mean(pred_velocity^2 * (1 + gate_weight * entropy))
```

解释：attention entropy 高的位置代表匹配不确定、结构复杂，因此对 velocity 施加更强刹车；entropy 低的位置允许更自由风格迁移。

验证结果：EC 最好，但 raw style 降一点。

## 8. 当前架构瓶颈

### 8.1 Raw style 天花板

K1 epoch7/8 raw CLIP-style 约：

```text
0.716 - 0.717
```

SaMST strict：

```text
0.7194
```

style 天花板来自三个因素：

1. 当前 style conditioning 是 style-id/domain prior，不是 reference image。
2. 推理 horizon 被 clamp 到 1，step_size 无法继续释放风格。
3. kinetic / skip / semantic routing 都偏内容保护。

### 8.2 内容-风格冲突

实验显示：

```text
去掉 kinetic: style 接近 0.716，但 LPIPS 0.6375，内容崩
去掉 SWD: LPIPS 0.349，但 style 只有 0.6708
```

这说明方法确实处在 style-content Pareto 边界附近，不是简单调一个权重就能双赢。

## 9. 下一步最值得做的架构改动

优先级从高到低：

1. `max_integration_horizon`：解除推理 horizon 1.0 上限，测试 `1.1/1.25/1.4`。
2. `semantic_paint_gain`：在 SemanticCrossAttn 中对 painted style delta 加增益，测试 `1.15/1.3/1.5`。
3. K schedule：前期 K=2 保结构，后期 K=1 或 0.8 释放风格。
4. domain prototype style map：用真实训练 latent 的 domain prototype 替代纯 learnable spatial prior。
5. reference-style conditioning：如果论文定位允许，再引入 reference latent/style image conditioning。

不推荐继续主推：

```text
w_color / gumbel color / strong color loss
```

原因是已经验证其内容代价过高。
